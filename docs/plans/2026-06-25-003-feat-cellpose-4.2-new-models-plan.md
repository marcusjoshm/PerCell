# feat: adopt Cellpose 4.2 models (cpsam_v2 / cpdino) — make the 4.x model selectable

## Overview

Cellpose **4.2.1.1** (June 2026) ships new built-in segmentation models —
`cpsam_v2` (improved CellposeSAM, "fewer spurious masks in low-contrast
regions"), `cpdino`, and `cpdino-vitb` (DINOv3 backbones) — selected via the
`CellposeModel(pretrained_model=...)` argument. PerCell4's Cellpose-4.x code
path was written when `cpsam` was the *only* 4.x model, so it constructs
`models.CellposeModel(gpu=gpu)` and **ignores the chosen model name entirely**.
The user can pick `cpsam`/`cyto3`/… in the GUI and CLI, but on 4.x it has no
effect.

This plan threads the selected model into the 4.x constructor via
`pretrained_model`, replaces the stale model list with the four 4.x built-ins
(default `cpsam_v2`), bumps the dependency floor to the version that ships the
new models, and updates the surfaces/docs that still claim "model is ignored on
Cellpose 4.x". The improved `cpsam_v2` default directly benefits PerCell4's
typically low-contrast fluorescence images.

---

## Problem Frame

PerCell4 wraps Cellpose in `src/percell4/adapters/cellpose.py`. Its
`build_cellpose_model()` branches on the installed major version: on 4.x it
returns `models.CellposeModel(gpu=gpu)` — dropping `model_type` because, at the
time, `cpsam` was the only 4.x model. Cellpose 4.2 changed that: there are now
four built-in 4.x models, and the API selects among them with
`CellposeModel(pretrained_model="cpsam_v2")`. The selectable model list
(`CELLPOSE_MODELS`) still mixes 3.x names (`cyto3`/`cyto2`/`cyto`/`nuclei`) with
`cpsam`, and the default is the now-superseded `cpsam`.

Net effect: PerCell4 cannot use any of the new, better models — the whole point
of the user's request ("take advantage of new features, like a new segmentation
model"). The installed dev environment is `cellpose 4.1.0`, which already
accepts `pretrained_model` but predates `cpsam_v2`/`cpdino` (those need 4.2.x),
so delivering the feature also requires bumping the dependency floor.

---

## Requirements Trace

- R1. A user can select and actually run any of the Cellpose 4.2 built-in models
  (`cpsam_v2`, `cpsam`, `cpdino`, `cpdino-vitb`) from both the GUI Segment tab /
  workflow dialog and the batch CLI — the choice changes which model runs.
- R2. The default model is `cpsam_v2` (the improved CellposeSAM), applied
  consistently across the GUI, the batch CLI, and serialized-config defaults.
- R3. The dependency pin guarantees the new models are available
  (`cellpose >= 4.2`), and the wrapper collapses to a single, correct 4.x path.
- R4. The single source of truth for the model list (`CELLPOSE_MODELS`) drives
  every selector; no surface hard-codes a divergent list.
- R5. Surfaces and docs no longer claim the model is "ignored on Cellpose 4.x";
  README, CLI `--cellpose-model` help, CHANGELOG, and module docs reflect the
  new selectable models and default.
- R6. A previously-saved workflow config / settings referencing a model no
  longer in the list (e.g. `cyto3`) degrades gracefully to the default rather
  than crashing or silently producing an invalid selection.

---

## Scope Boundaries

- Not adding support for arbitrary user-supplied **custom** Cellpose models
  (a file path / custom `pretrained_model`). The selector stays a fixed list of
  built-ins; a custom-model browse field is a separate future feature.
- Not retaining the Cellpose **3.x** code path. Bumping the floor to `>=4.2`
  makes the `models.Cellpose` (3.x) branch unreachable; it is removed, not kept
  as dead code. (Decision + risk below.)
- Not keeping the legacy `cyto3`/`cyto2`/`cyto`/`nuclei` names in the selector —
  these are Cellpose 1–3 models, superseded by the generalist 4.x models for
  this tool's use. Saved configs referencing them fall back to the default (R6).
- Not changing the diameter / flow / cellprob / min-size / niter / saturation /
  blur controls or their auto-scaling (niter auto-scaling for large cells is an
  intentional quality behavior and must be preserved).
- Not adding image-restoration / denoise model support (Cellpose3 restore) —
  out of scope for this plan.
- No GPU/torch install-path changes; the existing `gpu` extra is unchanged.

## Key Technical Decisions

- **Require `cellpose>=4.2,<5` and remove the 3.x branch.** The new models need
  4.2; PerCell4 already defaults to a 4.x model. Bumping the floor lets the
  wrapper collapse to one correct 4.x path instead of carrying an
  unreachable `models.Cellpose` (3.x) branch. Rationale: R3; simpler, matches
  reality. *Trade-off:* drops Cellpose 3.x — acceptable since the default was
  already 4.x `cpsam` and 3.x users upgrade via `pip install -U` (the `<5` cap
  is unchanged). Recorded as a risk.
- **Thread the model name via `pretrained_model`.** `build_cellpose_model()`
  passes `pretrained_model=<model>` to `CellposeModel`. Rationale: the exact,
  documented 4.x selection API (R1).
- **Default `cpsam_v2`.** Same SAM-ViTL architecture as `cpsam` but fewer
  spurious masks in low-contrast regions — a strictly-better default for
  fluorescence. Rationale: R2. *Trade-off:* re-running segmentation yields
  (improved) different masks than `cpsam`; `cpsam` stays selectable for
  reproducing prior runs.
- **`CELLPOSE_MODELS = ("cpsam_v2", "cpsam", "cpdino", "cpdino-vitb")`** — the
  four 4.x built-ins, default first; drop the 3.x `cyto*`/`nuclei` names.
  Rationale: R4; only reachable models are offered.
- **Unknown saved model → default.** Loading a config whose `model` is not in
  the current list resolves to the default with a warning. Rationale: R6;
  migrates old `cyto3` configs without a crash.
- **Keep the wrapper param name `model_type` as the public arg but treat it as
  the 4.x `pretrained_model` value.** Avoids renaming across ~6 call sites;
  update its default from `"cyto3"` to the resolved 4.x default. *(Renaming the
  param to `model` is an optional cleanup, deferred.)*

## Open Questions

### Resolved During Planning

- How does 4.x select a model? → `CellposeModel(pretrained_model="cpsam_v2")`
  (verified in Cellpose docs).
- Which version ships the new models? → 4.2.x (June 2026); floor bumped to `>=4.2`.
- Keep 3.x support? → No; floor bump makes it dead code, which is removed.
- New default? → `cpsam_v2`.

### Deferred to Implementation

- Whether `build_cellpose_model()` should pre-validate the model name against the
  installed Cellpose (clear error) or rely on Cellpose's own "model not found"
  error. Decide when touching the wrapper; a thin clearer-message wrapper is
  acceptable but optional.
- Exact mechanism for the niter auto-scaling preservation (leave the existing
  code path untouched vs. assert it still runs) — confirm against the real
  wrapper when editing.
- Whether `cpdino-vitb`'s hyphen needs any escaping in argparse `choices` /
  serialized config (expected fine as a plain string; verify at implementation).

  eliminating the duplicate so R4 holds going forward.
- In `artifacts.py`, change the fallback default to `cpsam_v2`, and when the

**Patterns to follow:**

  and `_cellpose_settings_form.py` (`addItems(CELLPOSE_MODELS)`).

- Integration: `seg_qc` re-run dropdown is populated from `CELLPOSE_MODELS`
  (same membership as the form), proving the duplicate list is gone.

**Verification:**

  `cyto*`; `pip install -e .` resolves Cellpose to a 4.2.x release.

## System-Wide Impact

- **Interaction graph:** the model string flows GUI form / workflow dialog /
  `seg_qc` re-run / batch CLI → `CellposeSettings.model` → `run_cellpose(model_type=…)`
  → `build_cellpose_model(pretrained_model=…)`. U2 is the one behavioral seam;
  U1 feeds it the right values; U3 only changes copy.
- **State lifecycle risks:** serialized workflow configs and `run_state.json`
  may carry an old `model` (e.g. `cyto3`); R6 fallback prevents a crash on load.
- **API surface parity:** GUI Segment tab, workflow config dialog, `seg_qc`
  re-run dropdown, and both batch CLIs (`batch-cellpose-laptrack`,
  `run_pipeline`) must all offer the same list — guaranteed by the single
  `CELLPOSE_MODELS` source once the `seg_qc` duplicate is removed (U1).
- **Unchanged invariants:** diameter/flow/cellprob/min-size/**niter
  auto-scaling**/saturation/blur behavior and the on-disk `/intensity`
  (never modified before inference) are untouched; only model construction
  changes. The `gpu` extra and torch install paths are unchanged.

## Risks & Dependencies

| Risk | Mitigation |
|------|------------|
| Bumping floor to `>=4.2` forces an upgrade for users on Cellpose 3.x / 4.0–4.1 | The cap `<5` is unchanged and `pip install -e .` upgrades within 4.x; the project already defaulted to a 4.x model. Document the bump in CHANGELOG; surface a clear error if an incompatible Cellpose is somehow present. |
| New default `cpsam_v2` changes segmentation outputs vs `cpsam` | Intended improvement (low-contrast); `cpsam` stays selectable to reproduce prior runs; called out in CHANGELOG. |
| Selecting a 4.2-only model on an older installed Cellpose fails to download | Floor `>=4.2` guarantees availability; optionally wrap Cellpose's "model not found" with a clearer message (deferred decision). |
| Dev env is `cellpose 4.1.0` — slow test for `cpsam_v2` can't run until upgraded | The mocked-`CellposeModel` unit tests (U2) verify threading without a download; the slow end-to-end test runs after `pip install -U cellpose` to 4.2.x. |
| Removing the 3.x branch could break a hidden 3.x assumption | The branch is provably unreachable once the floor is `>=4.2`; the adapter tests (mocked) and the slow test cover the remaining 4.x path. |
| Saved config references a dropped `cyto*` model | R6 fallback to default + warning; covered by a U1 test. |
